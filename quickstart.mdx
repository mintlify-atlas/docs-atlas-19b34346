OmniRoute is ready to answer requests the moment it starts. The `auto` model is pre-wired to keyless free providers, so you do not need an API key for any upstream service to complete this guide. From a fresh machine to your first routed AI response takes under three minutes.

<Steps>

### Install OmniRoute

<Tabs>
  <Tab title="npm (recommended)">
    ```bash
    npm install -g omniroute
    ```

    Requires Node.js `>=22.22.2 <23` or `>=24.0.0 <27`. If you see `ERESOLVE` or peer-dependency warnings during install, they are harmless — the package resolves them internally.

    To skip the post-install native warm-up in CI or on slow machines:

    ```bash
    OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute
    ```
  </Tab>
  <Tab title="Docker">
    ```bash
    docker run -d \
      --name omniroute \
      --restart unless-stopped \
      --stop-timeout 40 \
      -p 127.0.0.1:20128:20128 \
      -v omniroute-data:/app/data \
      diegosouzapw/omniroute:latest
    ```

    The default image sets `OMNIROUTE_MEMORY_MB=1024` — enough for the dashboard and light chat. Add `-e OMNIROUTE_MEMORY_MB=8192 --memory=10g` when running coding agents like Claude Code or Codex. See the [Installation guide](/installation) for the full RAM table.
  </Tab>
</Tabs>

### Start the Gateway

```bash
omniroute
```

OmniRoute starts on port `20128`. The dashboard opens automatically in your browser at `http://localhost:20128`. The OpenAI-compatible API is available at `http://localhost:20128/v1`.

<Tip>
  Run `omniroute --no-open` to suppress the automatic browser launch. Use `omniroute --port 3000` to change the default port.
</Tip>

### Connect a Free Provider

You can use OmniRoute without paying anything by connecting a keyless free provider. Open the dashboard at `http://localhost:20128`, navigate to **Providers → Add Provider**, and connect one of:

- **Kiro AI** — Free Claude access, ~50 credits/month per account. Click **Connect** (no API key required — uses a device-code OAuth flow).
- **OpenCode Free** — No authentication at all. Multiple models including DeepSeek V4 and Nemotron 3. Click **Connect** and it works immediately.
- **Pollinations** — No key needed. Provides GPT, Llama, Claude, Gemini, and more.

<Note>
  OpenCode Free and Felo are pre-wired into the `auto` combo on a fresh install, so the gateway answers immediately — even before you connect any provider via the dashboard. Connecting Kiro AI or additional providers improves routing quality and increases available quota.
</Note>

### Configure Your Coding Tool

Get your API key from **Dashboard → Endpoints** (or the **API Keys** page). This key authenticates requests to OmniRoute — it is not a key for any upstream provider.

Set the following in your IDE or CLI tool:

```
Base URL: http://localhost:20128/v1
API Key:  <your OmniRoute key from Dashboard → Endpoints>
Model:    auto
```

**One-command setup** for supported tools — OmniRoute writes each tool's config file directly:

```bash
omniroute configure codex      # writes ~/.codex/*.config.toml
omniroute configure claude     # writes ~/.claude/profiles/<name>/settings.json
omniroute configure opencode   # writes ~/.config/opencode/opencode.json
omniroute configure cline      # Cline CLI + VS Code extension settings
omniroute configure continue   # ~/.continue/config.yaml
omniroute configure cursor     # prints Cursor's in-app steps
omniroute configure aider      # ~/.aider.conf.yml
omniroute configure goose      # ~/.config/goose/config.yaml
```

Or launch any supported CLI directly with credentials injected per-process:

```bash
omniroute run claude   --model auto
omniroute run codex    --model auto
omniroute run opencode --model auto
omniroute run aider    --model auto
omniroute run goose    --model auto
omniroute run gemini   --model auto
omniroute run qwen     --model auto
```

### Verify Your Setup

```bash
curl http://localhost:20128/v1/models \
  -H "Authorization: Bearer YOUR_KEY"
```

You should see a JSON list of your connected models. Then send a real request:

```bash
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_KEY" \
  -d '{
    "model": "auto",
    "messages": [{"role": "user", "content": "Hello from OmniRoute!"}]
  }'
```

A streaming response confirms OmniRoute is routing correctly. Check **Dashboard → Monitoring → Logs** to see the full request detail, including which provider was selected and how many tokens were used.

</Steps>

## The `auto` Model Variants

Once you have multiple providers connected, you can tune the routing axis by using a specialised `auto` variant instead of the generic `auto`:

| Model ID | Optimises for |
|---|---|
| `auto` | Balanced default — sticks to your last good provider (LKGP) |
| `auto/coding` | Quality-first weights for code generation tasks |
| `auto/fast` | Lowest latency first |
| `auto/cheap` | Cheapest per-token first |
| `auto/offline` | Most quota / rate-limit headroom first |
| `auto/smart` | Quality-first + 10% exploration to discover better models |

All variants fall back automatically if the top-scored provider is unhealthy or rate-limited.

## Tokenized Compatibility URLs

Some tools — older VS Code extensions, certain Copilot integrations — cannot attach `Authorization: Bearer …` headers. For those, OmniRoute exposes tokenized alias URLs that embed the key directly in the path:

```
OpenAI catalog:    http://localhost:20128/vscode/YOUR_KEY/
OpenAI models:     http://localhost:20128/vscode/YOUR_KEY/models
OpenAI chat:       http://localhost:20128/vscode/YOUR_KEY/chat/completions
OpenAI responses:  http://localhost:20128/vscode/YOUR_KEY/responses
Ollama chat:       http://localhost:20128/vscode/YOUR_KEY/api/chat
Ollama tags:       http://localhost:20128/vscode/YOUR_KEY/api/tags
```

<Warning>
  Use tokenized URLs only for clients that genuinely cannot send `Authorization` headers. Standard `Bearer` authentication is always preferred because the key never appears in server logs or browser history.
</Warning>

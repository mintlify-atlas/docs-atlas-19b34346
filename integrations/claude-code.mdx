Claude Code communicates via the Anthropic Messages API and can be redirected to any compatible gateway through environment variables. OmniRoute accepts those requests and routes them across 350+ providers — swapping models, falling back on quota exhaustion, and compressing tokens — all transparently. You can point Claude Code at OmniRoute in seconds with the `omniroute setup-claude` command, or by setting two environment variables manually.

## How Claude Code connects to a gateway

Claude Code reads its gateway configuration from environment variables at startup. The two critical ones are `ANTHROPIC_BASE_URL` (the gateway root — **no `/v1` suffix**; Claude Code appends `/v1/messages` itself) and either `ANTHROPIC_AUTH_TOKEN` or `ANTHROPIC_API_KEY` for credentials.

| Variable | Purpose |
|---|---|
| `ANTHROPIC_BASE_URL` | Gateway root URL. Claude Code appends `/v1/messages`. **No `/v1` suffix.** |
| `ANTHROPIC_AUTH_TOKEN` | Sent as `Authorization: Bearer …`. Takes priority over `ANTHROPIC_API_KEY`. |
| `ANTHROPIC_API_KEY` | Sent as `x-api-key`. Used when `ANTHROPIC_AUTH_TOKEN` is not set. |
| `ANTHROPIC_MODEL` | Force a specific model, overriding the `/model` picker default. |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | Set to `1` to list `claude*` / `anthropic*` models from `/v1/models` in the native picker. |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS` | Cap output tokens per response, e.g. `65536`. |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW` | Token threshold for auto-compaction. Set below the model's real context window. |

<Warning>
Environment variables are read **once at startup**. Restart Claude Code after changing any of them, or use `omniroute launch` which sets all of them automatically.
</Warning>

## Quick start

<Steps>
  <Step title="Generate per-model profiles">
    Run `omniroute setup-claude` against a local OmniRoute instance. It fetches the live `/v1/models` catalog and writes one profile per model to `~/.claude/profiles/<name>/settings.json`.

    ```bash
    omniroute setup-claude
    ```
  </Step>
  <Step title="Launch Claude Code with a profile">
    Use `omniroute launch` to inject the auth token from your active context and start Claude Code pointing at OmniRoute.

    ```bash
    omniroute launch --profile glm52
    ```
  </Step>
  <Step title="Verify the connection">
    Inside Claude Code, open the `/model` picker. If `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` is set and Claude Code is v2.1.219+, you should see models from your OmniRoute catalog.
  </Step>
</Steps>

## Auto-configure with `omniroute setup-claude`

`omniroute setup-claude` fetches the live model catalog from a running OmniRoute and writes one `settings.json` profile per model to `~/.claude/profiles/<name>/`. Profile names match those generated by `setup-codex` (`glm52`, `kimi-k27`, `deepseek-pro`, and so on).

```bash
# Local OmniRoute on port 20128
omniroute setup-claude

# Only generate profiles for GLM and Kimi models
omniroute setup-claude --only glm,kimi

# Preview without writing anything to disk
omniroute setup-claude --dry-run

# Override the default port
omniroute setup-claude --port 20129
```

An example generated profile looks like this:

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://localhost:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000"
  }
}
```

<Note>
The auth token is **never written to a profile file**. Use `omniroute launch --profile <name>` to inject `ANTHROPIC_AUTH_TOKEN` from the active context, or export it yourself and run `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude`.
</Note>

## Manual configuration

If you prefer to configure Claude Code without running the setup command, export the two required variables before launching `claude`:

```bash
export ANTHROPIC_BASE_URL="http://localhost:20128"
export ANTHROPIC_API_KEY="YOUR_OMNIROUTE_API_KEY"
claude
```

To retrieve the onboarding snippet from the dashboard (which auto-fills the base URL for your instance), go to **Dashboard → CLI Code**. The snippet never includes your key — paste it over the placeholder.

```jsonc
// Paste into ~/.claude/settings.json under the "env" key
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://localhost:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1"
  }
}
```

## Remote server setup

To point Claude Code at an OmniRoute instance running on a remote VPS or within a Tailnet, pass `--remote` and `--api-key` to the setup or launch commands:

```bash
# Generate profiles baked with the remote URL
omniroute setup-claude --remote http://YOUR_SERVER:20128 --api-key YOUR_KEY

# Launch Claude Code directly against the remote
omniroute launch --remote http://YOUR_SERVER:20128 --api-key YOUR_KEY
```

Once you have run `omniroute connect <host>` to store a context, you can omit those flags — the active context supplies them automatically.

## MCP integration

Claude Code can also connect to OmniRoute's MCP server, which exposes 110 tools for routing, cache, compression, memory, and more. Add it with a single command:

```bash
claude mcp add-server omniroute --type http --url http://localhost:20128/api/mcp/stream
```

This gives Claude Code access to OmniRoute's full MCP tool catalog while it runs. See the [MCP integration guide](/integrations/mcp) for the complete list of tools and scopes.

## Discovery aliases (surfacing non-Claude models in the picker)

Claude Code's native `/model` picker only lists model IDs that begin with `claude` or `anthropic`. OmniRoute can mirror any enabled model under a `claude/…` alias so it passes that filter:

```
kimi/kimi-k2.6   →  claude/kimi/kimi-k2.6   "Kimi K2.6 (OmniRoute)"
glm/glm-5.2      →  claude/glm/glm-5.2      "GLM 5.2 (OmniRoute)"
```

When you select one of these in Claude Code, OmniRoute strips the `claude/` prefix before routing. This feature is **off by default** and is controlled at three levels:

| Level | Where |
|---|---|
| Model | Provider detail page → per-model "Expose in Claude Code" toggle |
| Provider | Provider detail page → provider-level toggle |
| Global | Settings → Feature Flags → `EXPOSE_CC_DISCOVERY_ALIASES` (default off) |

<Warning>
Claude Code assumes a 200K context window for any model ID it doesn't recognize. For models with larger windows (e.g. Kimi K2's 256K), set `CLAUDE_CODE_AUTO_COMPACT_WINDOW` to a value below the real window so auto-compaction doesn't fire prematurely. The generated profiles handle this per model.
</Warning>

## Auto-sync profiles

OmniRoute can regenerate profile files automatically whenever a provider sync changes the live model catalog. This is **opt-in and off by default**. Enable it from **Dashboard → CLI Code → "CLI profile auto-sync" → Claude Code**, or set:

```bash
OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true
```

When enabled, OmniRoute only writes profile files — it never changes your active `~/.claude/settings.json`, credentials, or auth.

## Troubleshooting

<Accordion title="Claude Code ignores the gateway">
  Confirm `ANTHROPIC_BASE_URL` has **no `/v1` suffix** (correct: `http://localhost:20128`, wrong: `http://localhost:20128/v1`). Restart `claude` — environment variables are read once at startup. Use `omniroute launch` to avoid this pitfall entirely.
</Accordion>

<Accordion title="The /model picker is empty or missing gateway models">
  Requires Claude Code v2.1.219+ and `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`. Only `claude*` / `anthropic*` model IDs appear in the picker; force any other model with `ANTHROPIC_MODEL=<id>`, which is what generated profiles do.
</Accordion>

<Accordion title="400 Ambiguous model 'claude-…'">
  This happens when both the Claude Code (`cc/…`) and Claude (`claude/…`) providers are connected — the bare ID matches two routes. Fix it by pinning a prefixed ID: `ANTHROPIC_MODEL=cc/claude-opus-4-8`, or enable **Prefer Claude Code for unprefixed Claude models** on the Claude provider page (or set `OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true`).
</Accordion>

<Accordion title="Auth errors after loading a profile">
  The profile holds no token by design. Use `omniroute launch --profile <name>` to inject `ANTHROPIC_AUTH_TOKEN` from the active context, or export it yourself: `export ANTHROPIC_AUTH_TOKEN=<key>`.
</Accordion>

<Accordion title="Profiles don't isolate sessions">
  Each profile is a distinct `CLAUDE_CONFIG_DIR`. Verify it is set correctly inside the active session: `echo $CLAUDE_CONFIG_DIR` should point to `~/.claude/profiles/<name>`.
</Accordion>
